3Bugs the live click-through caught

Build, lint, and tests all passed for Batch 4 before any of these were visible — none of them were the kind a test suite catches. All three only showed up once I actually clicked through the flow in your Chrome.

1 · Convert always failed — customers.address is validated on every insert
BrokeA DB trigger requires any customer's address to already be in the "street, barangay, city, province" shape — a storefront customer's free-text address almost never matches that, so every real Convert would fail.
FixedConvert now opens a small "complete the address" form (reusing the same address fields used elsewhere) only when needed, prefilled with what the customer already typed.
2 · Convert added to cart, then landed on a 404
BrokeCode navigated to /reseller/cart, but the Cart page is actually mounted at /cart — the item was added correctly, the Reseller just got a dead page right after.
FixedPointed the navigation at the real route.
3 · Checkout crashed outright (pre-existing, unrelated to this feature)
BrokeCheckout.jsx referenced two functions inside a useEffect dependency array before they were declared further down the file — a hard crash on every load, for any reseller, whenever the cart actually had items. This bug predates this feature; it just had never been reachable in earlier testing because the cart was never getting populated.
FixedReordered the declarations above the effect that uses them — no logic changed, purely a move.
